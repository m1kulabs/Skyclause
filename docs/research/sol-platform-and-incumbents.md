## Devices and measurements

- A Pi can report actual SoC temperature with `vcgencmd measure_temp` and throttling flags with `get_throttled`. These describe its hardware state, not room temperature or household energy use. The Pi documentation also distinguishes current flags from historical occurrence flags. [Raspberry Pi OS utilities](https://www.raspberrypi.com/documentation/computers/os.html#vcgencmd).
- Browser microphone capture requires a secure context and permission. A user can deny or leave the prompt unanswered. [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia). Build an explicit unsupported/permission-denied state, with no invented reading.
- Automatic gain control and noise suppression can alter readings. Actual settings and capabilities vary by track/device. [MDN settings](https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack/getSettings), [capabilities](https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack/getCapabilities). Relative levels on one phone are not calibrated dBA, comparable cross-phone measurements, a nuisance violation, or medical evidence.
- WebRTC statistics describe an actual peer connection and vary by statistic and browser. [RTCStatsReport](https://developer.mozilla.org/en-US/docs/Web/API/RTCStatsReport). A short HTTPS upload test is only evidence about that request to that endpoint; it does not establish Zoom/Teams call quality. A second phone's reading cannot certify a presenting laptop's microphone.
- Hardware inventory is limited to phones and a Pi 5 with 8 GB. A camera module, external microphone, environmental probe, smart plug, UPS and extra radios are not assured. Phone microphones and sensors are usable only after checking the actual devices. Browser background capture is not assumed reliable.

## Phone experiment signals

Two additional original Reddit pages were opened and their relevant bodies/comments read during synthesis. A fresh-context researcher also read a relevant original phyphox community thread. They provide bounded transfer evidence for FieldPair, not APU validation:

- [Home magnetic-dipole experiment](https://www.reddit.com/r/AskPhysics/comments/mgblbj/), March 2021 according to Reddit's thread calendar index; the opened body gives only a relative age, so the exact posting day is not claimed. The author describes repeated disagreement with an expected relationship despite several setup checks. The author later reports that measuring farther from the magnet resolved it. This supports the importance of setup context; it does not establish a unit error, incompatible team captures, or a problem that schema validation or an LLM would have solved. Do not use agreement with an expected value as the acceptance rule for science.
- [phyphox user discussion](https://www.reddit.com/r/codyslab/comments/xhn85m/), September 2022 by Reddit's calendar index; exact comment day not verified. One complete comment asks for simultaneous sensor outputs, describes personal flight measurements, and says accuracy is unknown. Another says they used the app in school. These are self-reports about actual sensor use, not evidence that remote groups need automatic recollection. Unrelated speculative claims elsewhere in the discussion are not adopted.

- [About fluctuating sampling rate, phyphox forum](https://phyphox.org/forums/showthread.php?pid=4887&tid=2356), 10 June 2026; entire thread read by the researcher on 5 November. A user reports requested accelerometer rates differing from actual rates on an iPhone, then [cross-platform experiment-file loading trouble](https://phyphox.org/forums/showthread.php?pid=4892&tid=2356) on 18 June. Replies distinguish OS sampling requests from guarantees and application version from experiment format. The user [confirms resolution](https://phyphox.org/forums/showthread.php?pid=4912&tid=2356) on 13 July. This is a concrete reason to record actual sampling and configuration, **and counter-evidence** against needing a new product: existing support solved the case. One custom-experiment user, unknown student status/location; no APU, prevalence or new-agent demand established.

No participant was contacted, no original linked data file was analyzed, and no phone measurement was performed. The product should remain on research hold unless a real group supplies a recurring protocol-coordination problem.

## Implications for selection

Choose a student-owned workflow with physical evidence that changes a decision. A device-to-dashboard-to-ticket chain is easy for many AI-equipped teams to reproduce. More defensible hypotheses preserve a difficult relationship: which hardware state belongs to which revision; which sensor readings can be compared; which mutually agreed quiet period remains achievable.

Cloud is useful for cross-member state and asynchronous reasoning, while the network must expose delivery, acknowledgement, freshness and failure. Edge code should handle measurement integrity and immediate rules. Removing AI should leave understandable rules; Gemini earns its place by reconciling evidence with a changing plan and preparing a specific next action, rather than replacing a threshold comparison.
