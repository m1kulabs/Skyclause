# Project lifecycle implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete #137's project lifecycle and callable create/archive backend services.

**Architecture:** DB repositories perform atomic writes within the caller transaction. API services enforce project visibility and map exact DTOs; registry handlers use existing auth, tenancy, idempotency and permission guards. Keep all source data absent until actual ingestion.

**Tech Stack:** TypeScript, Drizzle/Postgres18, Hono, Zod, Vitest, Bun.

**Spec:** docs/superpowers/specs/2026-11-09-p1-projects-137-design.md; authoritative #79/#137 snapshots copied into this plan's SDD workspace.

## Global Constraints

- IDs UUIDv7, wire snake_case, instants RFC3339 UTC. Only packages/db holds SQL, migrations, policies or connections.
- Services accept existing {principal,tx}; createProject/archiveProject never open nested transactions.
- Both packs and both default sheet version1 configurations are created; Sky follows selection, Crowd always starts off. SLA defaults600/7200 seconds.
- Use exact existing defaults and canonicalHash. System version1 has no ledger entry and no human publisher impersonation.
- No runtime synthetic windows, readings, sources, calls or sample data. Isolated test factories/doubles are authorized.
- Archive/restore idempotent, preserve first archived_at, no invented audit/event beyond contract.
- No clause engine source changes. Only narrowly adding JSON default subpath exports in packages/clauses/package.json is permitted; #131 separately owns its dependency additions.
- Every shell command starts rtk; root owns pushes, PRs, merges and closure; no agents delegated by implementer.

## Review Focus

- Mid-bootstrap failure must roll back project, sheets, versions, packs and analytics together.
- Same-org narrowed OAuth grants must not leak another project through list/get/summary.
- Multiple in-force calls must use highest mode and valid span/night lifetime, not just newest call.
- Nullable configuration must stay null without guessed schedule/hours/dates.
- Concurrent same-slug creation must produce one project and the precise slug-taken problem, not a500 or duplicate rows.
