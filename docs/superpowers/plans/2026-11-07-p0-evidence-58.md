## Review Focus

1. A quoted request or an unsubscribe reply under a still-valid request subject must not become a fresh evidence/call request. Task 1 pins this alongside MYT year boundaries.
2. An interval's first visible gauge stamp may need measurements before the requested start; revisions or a missing warm-up stamp must not fabricate a total. Task 2 covers this on real captures and controlled omissions in tests.
3. Private data can hide in nested ledger bodies, grade explanations, extra row keys and malformed MIME. Tasks 2 and 4 assert that these never enter an agent pack or notification.
4. A provider send may succeed while the response or notification-log append is lost, and a retry may cross a rota shift. Task 3 verifies reconciliation and a frozen destination.
5. A new arrival, mid-page stop or failed cursor write must not drop older unprocessed mail. Tasks 3 and 4 exercise frozen query bounds and replay of a partly processed page.

### Task 3: Orchestrate durable inbox processing and notifications

**Files:** Create `evidence.ts`, `evidence.test.ts`, `evidence-notification.ts` and `evidence-notification.test.ts`.

**Interfaces:**

- Consume Tasks 1–2 interfaces. Produce `EvidenceInboxMessage` with `id`, `receivedAt`, private `fromAddress`, `subject`, plain `body`, `inInbox`, `sentByOwner`, `mailerDaemon` and optional decode-error code. Private message fields never reach the pack builder.
- Produce `EvidenceInboxCursor` with `activatedAt`, `lowerBound`, optional frozen `upperBound` and `pageToken`. Produce `EvidenceMessagePage` with `messageIds: string[]` and optional `nextPageToken`; fetch message details lazily after checking recorded IDs.
- Produce `EvidenceInboxPorts` methods: `now(): Date`, `ownerEmail(): string`, `projectSlug(): string`, `cursor(): EvidenceInboxCursor | null`, `saveCursor(cursor): void`, `listMessages(cursor): EvidenceMessagePage`, `message(id): EvidenceInboxMessage | null`, `evidenceRows(): Row<'evidence'>[]`, `packRows(): EvidenceStoredRows`, `appendEvidence(row): void`, `unsubscribe(address, at): void`, and `notices: EvidenceNotificationPorts`.
- Produce `runEvidenceInbox(ports: EvidenceInboxPorts): EvidenceInboxReport`; report fields are `initialized: boolean`, `processed: string[]`, `skipped: string[]`, `pendingNoticeIds: string[]`, `pageComplete: boolean`, and `errors: { requestId?: string; code: string }[]`. Error details contain no addresses or request text.
- Produce private `EvidenceNoticeIntent` with request ID, first-processing `routingAt`, controlled marker and optional frozen recipient, draft ID/thread ID and provider message ID. It contains no pack/request body. Produce `EvidenceNotificationPorts` for loading/saving/removing/listing intents, reading an existing notification/evidence row, retrieving the requester's private address, resolving duty at an instant, hashing an ID, creating/getting/sending a draft, finding Sent candidates and appending a notification.
- Produce `deliverEvidenceNotice(requestId: string, ports: EvidenceNotificationPorts): EvidenceNoticeResult`. Result statuses are `sent`, `reconciled`, `already_logged` (with a real `gmailMessageId`), `pending` (with an address-free error code), or `skipped` for a persisted non-notifiable kind. Draft/Sent DTOs expose provider ID, recipient, controlled subject and decoded plain body; these remain in the private delivery layer. A draft ID is distinct from its contained message ID and the final sent message ID.
