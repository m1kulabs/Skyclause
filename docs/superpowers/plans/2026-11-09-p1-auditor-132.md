# Auditor Tick and Findings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement #132's worker-owned check registry, tenant-safe auditor tick, durable open/recovery transitions and completion heartbeat.

**Architecture:** The existing 15-minute worker batch runs checks sequentially on its shared SYSTEM connection. Each check/org gets a separate real transaction; a revocable Drizzle session guards its queries, while the open-finding unique index arbitrates concurrent transitions. Check functions and the existing Notify/EmailTransport contracts remain unchanged.

**Tech Stack:** TypeScript, Bun, Vitest, Drizzle ORM 0.45.4, pg 8.23.1, PostgreSQL 18, OpenTelemetry.

**Spec:** docs/superpowers/specs/2026-11-09-p1-auditor-132-design.md; authoritative issue-132.md/issue-79.md copied into this plan SDD workspace. Independent AGY Argon High execution is authorized by the user, with one writer in this isolated worktree.

## Global Constraints

- "IDs are UUIDv7; instants RFC 3339 UTC"; check clocks use `Instant` strings and stored instants use timestamptz.
- "Only packages/db holds SQL text, migrations, policies, triggers and connections"; apps depend on packages, never the reverse.
- "Other tickets register their own checks; this ticket registers none".
- "A platform check ... runs once per tick under withSystem, with projectId null"; org checks default to per-org `withTenant`, system principal job `auditor`.
- "An open finding is unique on (check, org_id, project_id, key) where recovered_at is null, NULLS NOT DISTINCT".
- "A check that throws or exceeds 20 s for an organisation is logged with its name and counted"; other checks continue and its findings do not recover.
- "The tick never starts runs or writes audit_event"; it runs on the 15-minute batch, never the database-free minute tick.
- Every shell command starts `rtk`. Use task Postgres `SKYCLAUSE_DB_PORT=56439`, already ready; do not create another database service.
- Tests may use doubles; production must use real dependencies. Source closure requires lint/typecheck/full tests/seed-check; important live acceptance transfers to a linked follow-up under existing authorization.

## Review Focus

1. A check retains a builder/prepared statement/nested Tx and resumes after timeout: its SQL must be rejected before touching the shared connection (Phase 2).
2. Two true concurrent transactions open/recover the same nullable identity: exactly one transition wins and notifies (Phases 1 and 3).
3. SQL failure for organisation A: rollback must leave A's previous conditions open and allow B to run (Phases 2 and 3).
4. A stale tick finishes after a newer finding opens: it must not recover a row with opened_at later than its clock (Task 1).
5. Staff list contains whitespace/duplicates or mail partially fails: normal sends are per unique address; failure semantics and the real-mail guarantee gap stay explicit (Task 3).

#### Phase 2: Bound check execution without leaking SQL across transactions

**Interfaces:** Export `runAuditCheck<T>(tx: Tx, run: (scoped: TxHandle) => Promise<T>, timeoutMs?: number): Promise<T>` from db; default `timeoutMs=20_000`. It returns only a complete successful result; failure throws after revoking and draining the scoped database work. The optional override is an internal test seam, not a change to RegisterAuditCheck.

**Installed-API basis:** `NodePgTransaction` and `PgDialect` are exported constructors; `Tx._.session`, `_.schema`, `_.fullSchema`, `_.tableNamesMap` are available in installed Drizzle typings. Builders, relational queries and prepared statements execute through `session.prepareQuery(...).execute/all`; nested `NodePgTransaction.transaction` reuses its session. Implement a separate scoped `PgSession` delegate and `NodePgTransaction` facade, never patch the real session/client, mutate pg queues, access private pg activeQuery, or use pg query_timeout as cancellation.

- [ ] Write failing `auditor-scope.test.ts`: `late builders never execute`, `prepared statement cannot outlive scope`, `nested transaction cannot outlive scope`, `queued statements expire before submission`, `slow SQL cancels before next transaction`, `SQL error leaves next org usable`, `normal return revokes detached work too`. Capture ordinary, prepared, relational and nested builders; after expiry and a subsequent transaction, execution rejects and a probe table stays unchanged.
- [ ] Run `rtk env SKYCLAUSE_DB_PORT=56439 bun run test packages/db/test/auditor-scope.test.ts`; expect missing helper failure.
- [ ] In check-scope.ts create a new NodePgTransaction using a fresh PgDialect, the delegated scoped session and the existing public schema metadata; copy principal/orgId. The delegate wraps prepared execution, including `all`; preserve fluent prepared methods returning the guarded wrapper (`setToken` must not expose the unguarded prepared object). Its count implementation must route through guarded execution; nested savepoints retain the same session. Pass only this facade to the check.
- [ ] Give that session one absolute monotonic deadline and a private serial query queue. Before every actual query, check the lease, set transaction-local `statement_timeout` on the original Tx to the remaining positive milliseconds, recheck the lease, then execute the delegated query. Queued requests recheck at execution, so they never reach pg after expiry. SQL errors poison the check; even a callback that catches a database error cannot become a successful result.
- [ ] Race only the callback result against a handled deadline promise. On expiry, error or normal completion, close the lease immediately, clear timer, reject queued work, and await the queue's active operation settling before returning/throwing. PostgreSQL statement_timeout cancels already submitted SQL; the caller's withTenant/withSystem then awaits its real rollback before the shared connection can be reused. Observe any late callback rejection. Restore the previous local statement_timeout only on successful draining, using original Tx before reconciliation.
- [ ] Test real `pg_sleep` with a short injected deadline, SQLSTATE 57014 or wrapped cause, no late writes, and a successful following transaction in the same shareSystemConnection. Timer-only tests use unresolved/deferred callbacks and prove later resolution cannot submit SQL. Include concurrent query requests and callback success with detached work; no unresolved query may survive the helper.
- [ ] Run scope/store/shared-connection tests; expect PASS. Commit: `feat: guard auditor check deadlines`.

**Explicit intrinsic limit:** JavaScript cannot interrupt synchronous CPU loops or cancel arbitrary third-party promises through the unchanged `run(tx, now)` contract. The guard makes late async callbacks unable to use their DB scope; it does not promise to terminate arbitrary application code. A broken database transport that cannot drain/rollback is a fatal tick failure: emit no heartbeat and do not reuse the connection. If installed Drizzle paths cannot all be guarded as specified, keep this task/source acceptance open and report the failing test; do not substitute an unguarded Promise.race.
