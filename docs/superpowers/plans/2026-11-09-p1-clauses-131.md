# P1 clause engine implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace b-clauses placeholders with the deterministic CEL engine in #131.

**Architecture:** Keep public contracts and canonical hash; add focused private validation, snapshot and evaluation modules. All clocks and source facts enter through arguments; simulation is test-only.

**Tech Stack:** TypeScript, @bufbuild/cel 0.6.2, Vitest, fast-check, Playwright, Bun and Node.

**Spec:** docs/superpowers/specs/2026-11-09-p1-core-design.md; GitHub #79 and #131. Authoritative issue snapshots are in /Users/jeremywoon/.codex/artifacts/skyclause-p1-core-20261109/issue-{79,131}.md.

## Global Constraints

- packages/clauses runtime dependency is @bufbuild/cel 0.6.2 only; no clock or I/O, no Node built-ins in the browser bundle.
- Preserve public signatures from packages/clauses/src/types.ts and published defaults; do not change the contract to fit implementation.
- Ages are whole seconds; history includes only readings received and polls started at or before tEval.
- Required unbound or non-fresh inputs block, with sourceId null when unbound. Optional unavailable inputs are absent to has().
- Two missed intervals mean stale. First good reading after stale/error is recovered, next distinct good reading is fresh.
- No call applies only when a blocked clause could exceed the highest fired mode; not_open neither fires nor blocks.
- Test doubles and simulated data stay in tests. No live rows or emails are created.
- Only this issue’s package, dependency lock, scoped documentation and one ownership report may change.

## Review Focus

- CEL forbidden constructs, field typing and source offsets: reject invalid functions/types at their original positions.
- Arrival after tEval and equal-time revisions: snapshots never leak future receipts or depend on input array order.
- Partial rainfall grids and source errors: absent data cannot turn into zero rainfall or a clean verdict.
- Span opening/end boundaries and zero-length waves: preserve not_open/openFrom, inclusive last sample and frozen completed spans.
- JSON round-trip of verdicts: explain retains condition, wording and input provenance without process-local metadata.
