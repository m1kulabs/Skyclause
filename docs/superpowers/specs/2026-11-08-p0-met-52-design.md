## Source parsing

- Warning URL is exactly `https://api.data.gov.my/weather/warning/`, including its slash. Forecast URL is `https://api.data.gov.my/weather/forecast/?contains=Kuala%20Lumpur@location__location_name`.
- Each handler makes at most one fresh HTTP request. Both share four requests per minute; no internal HTTP retry. A 429 is an error and the next scheduled invocation retries. Own scheduled cadences produce at most two fresh requests in a minute; manual checks stay within four. This is maintained by cadence/manual procedure and the provider's real 429 response, without a new local quota scheduler, sleeping loop or invented HTTP outcome. Recovery reads Drive and makes no weather HTTP request.
- Validate complete responses before feed-data writes. Warnings are arrays with nested warning_issue containing issued/title_en/title_bm. All source text strings are preserved without trimming, case changes, HTML processing or translation. Actual nullable instruction_en/instruction_bm become blank cells; other required published text fields must be strings. Missing keys or invalid structural types are schema errors. Source string values remain data, never executable instructions.
- Parse issued and non-null validity as calendar-valid MYT instants with explicit +08:00; reject rollover and reversed validity. A null validity stays blank. Build warning_key from normalized issued, exact title_en and normalized valid_from, joined by the specified middle dots. Equal duplicate keys/published fields collapse; conflicting representations of one key within one response are an error.
- names_kl follows #52: not No Advisory, no Rough Seas in the title, and Kuala Lumpur in text_en or text_bm, case-insensitively. Heading alone does not qualify.
- Forecast parsing admits only exact location_id Ds058. Preserve its date and five forecast/summary strings, numeric integer temperatures and source wording. Validate calendar dates and min/max consistency. No target location in a valid response is an explicit source-content error. Identical duplicate dates collapse; conflicting days are an error. afternoon_thunderstorm is a case-insensitive Ribut petir substring check.
- Refuse any cell-bound source/derived field over 50,000 JavaScript string units; never truncate. Preserve valid UTF-8 transport bytes exactly and reject undecodable content as a schema error with the actual HTTP status.

## Stored versions and validity

Warnings are versioned by key. Compare published canonical fields against the newest stored revision, excluding receipt/poll metadata and last_seen_at. Same fields update only that active revision's last_seen_at, monotonically; changed fields append a new row with original source strings and this receipt's first_seen/poll/status/latency. Older revisions retain the last time their own representation was seen. A source reverting A→B→A appends a new A revision; do not revive an older physical row. Null versus empty optional instructions share the schema's blank representation, while their different raw bytes are still archived.

Forecasts compare only against that date's newest stored Ds058 row. Append changed published fields; equal days append nothing. Native date cells normalize to YYYY-MM-DD before comparison. Every warning append refuses missing issued, first_seen_at, HTTP status or latency, satisfying SIG-1.

Share a pure in-force predicate: No Advisory is false, missing/invalid validity is false, otherwise overlap is inclusive. Keep KL qualification and legacy marine-text exclusions separate from temporal validity. Share latest-per-key selection before qualification, so an older names_kl=true or later-valid revision cannot survive a replacement that removes it. Existing indicators currently scan old versions; this integration corrects that behavior. Preserve the indicator's minute-bucket as-of eligibility and the evidence pack's exact as-of eligibility; filter eligible rows before selecting the latest version. Use issued then first_seen_at, with later physical order breaking ties, matching the existing evidence semantics. Historical row absence alone does not invent a cancellation; published validity remains authoritative.

On each handler's first configuration pass, add only its missing compatible source row and populate the six DESIGN glossary pairs only if the glossary is wholly empty. Preserve existing configuration and human edits. These are configuration writes, not fabricated observations. A failed fetch may still leave initialized configuration, but writes no warning/forecast/raw-body data or last_seen changes. Warning source is met_warning / met_warning, cadence 10, stale threshold 20; forecast is Ds058 / met_forecast, cadence 360, stale threshold 720. Both are polled with licence `CC BY 4.0, MET Malaysia via data.gov.my`.

## Raw archives and recovery

Archive exact successful response bytes under the known RAW_FOLDER_ID's met child folder. Names are warning-YYYYMMDD-HHmmss.json or forecast-YYYYMMDD-HHmmss.json using actual receipt time in MYT. Create a new file only when bytes differ from the last committed body of that kind; changed bytes mean outcome ok even if no canonical row changes. Identical bytes mean unchanged. Successful polls always reference the matching actual raw file ID, including reuse for an unchanged body, so row provenance remains verifiable.

Drive, Sheets and Properties do not form a transaction. Before any feed-row writes, save a small feature-owned pending receipt containing kind/version, original poll UUID/metadata, actual archived body file ID and byte digest. The body itself stays in Drive, never a property. Recover this receipt before a new fetch for that kind, preserving original received_at rather than making recovered data appear newly fetched. Parse and hash-check its actual archived bytes; never use repository captures for recovery.

Idempotent upserts recognize rows already written by that poll ID, preventing duplicate versions after partial writes. Write/flush rows and last_seen changes, then append/flush the original poll before clearing the receipt. If the poll persisted before an exception, reconcile by exact poll ID instead of writing it twice. Never advance the committed-body reference or clear pending state before its durable poll. Existing raw-file lookup uses committed poll references. A storage failure propagates as storage failure; it is not an HTTP status-0 source outcome. A raw file left orphaned by failure before receipt save may remain; do not delete unrelated or committed evidence.

A current non-2xx, thrown fetch or schema error writes one error poll and no new feed data/archive. Successfully recovering an earlier real receipt retains its original provenance and does not substitute for a failed current fetch. Invalid present receipt state or missing/corrupt referenced archives is an explicit storage error, not permission to discard it or invent a new baseline.

## Native integration

Use a feature-specific native storage adapter composed by a thin gas factory to avoid growing unrelated service logic. Raw HTTP exposes original bytes and validated UTF-8 text; request identity encoding and non-2xx status remain explicit. Store and read only the two owned pending-receipt keys. Resolve met beneath the known raw folder, never a global name search. Create files from the exact byte blob and use the existing literal-string writer for source text. Target only last_seen_at cells on updates; other published/provenance cells remain immutable.

Export parameterless pollMetWarnings and pollMetForecast under one outer lock each, invoking the unlocked evaluation once after recorded work, including error outcomes. Register exactly the 10-minute and 6-hour pilot-only entries. Add a read-only verifyMetWarningText function: for every persisted warning revision, join its poll to the actual raw file and compare text_en/text_bm to the corresponding source record. Report compared/matched counts and explicit missing/mismatch errors; zero rows is not positive live proof.

Keep recovery, latest-body lookup and comparisons bounded to needed public columns and MET raw files. No private subscriber/rota/window columns or unrelated property values enter the ports. Do not add a new scope, send mail, deploy the shared pilot or install dev timers.

## Author decisions

Canonical blank instructions preserve explicit source absence; latest-version last_seen belongs to the representation actually seen. Reusing raw_file_id on unchanged successes strengthens verifiable provenance without creating files. A small pending receipt is necessary to preserve the row→poll→raw chain across partial writes; it is recovery of a real prior fetch with original time, not a fresh-source fallback. Latest-row qualification and preserved per-consumer clock resolution prevent stale warning versions from firing clauses. The fresh builder asked whether four-per-minute should be locally runtime-enforced. The issue's cadence, single-fetch/no-retry behavior, real 429 handling and bounded manual procedure resolve it without a new quota service. No remaining builder question changes the plan. Source/record examples are never runtime defaults.
