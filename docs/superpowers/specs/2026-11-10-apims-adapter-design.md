## Load-bearing rulings

These must be recorded under #123/#79 through the contract-change route before landing. Root has accepted ruling 1: historical class is optional while latest still requires the real class. The two preflight policies below resolve the receipt and discovery gaps; no broader implementation scope is added.

1. Preserve absent historical class: change the metric payload to `{class?: string, param: string}`. Latest still requires published `CLASS`; history omits the property when absent. Never derive a category from API, substitute empty text, copy latest class, or emit `null` under a string type. This narrow additive schema change is necessary for the real history payload.
2. Add opt-in source-isolated parsing and grouped backfill capabilities below. Keep current adapters' behavior by default. This is a contract change because #79's runner clarification explicitly said signatures were unchanged; no APIMS-kind branch in generic core is acceptable.
3. Interpret the one-map-request-per-slot budget literally across latest polling, catalogue and probes. A durable slot claim owns the single physical GET. Catalogue/probes may inspect only that same slot's successful captured bytes, preserving its actual timestamp and request identity; unavailable, failed or prior-slot bytes are not a fallback. Never make a second GET to satisfy a probe or discovery. Preserve the existing global physical-request ingestion receipt: a captured or already-ingested cohort cannot be widened. Newly eligible sources outside the frozen cohort are explicitly unavailable until the next slot, followed by the ordinary ingest batch. APIMS discovery is a pure catalogue capability with no default transport; only the generic slot owner may initiate its capture. This requires a small generic runner capability beyond an adapter-only implementation.
4. Preserve the issue's terminal state-level backfill rule: any earlier backfill poll for the state prevents a new history batch, including a failed one. This means a station bound after a state's completed batch may lack three mornings until live observations accumulate. First-bind day-one history is guaranteed only for the stations included in the initial eligible state's snapshot and only if DOE returns the required observations. Changing that rule to per-station retries or rolling state generations would increase the stated budget and requires a separate explicit ruling; this plan does not do it.
5. No-retry means no HTTP retry on failure. Retain #79's honest crash qualification for history: death before durable bytes can repeat a GET on recovery. For the stricter mapcaqm slot cap, do not reclaim a consumed slot for another GET after an ambiguous crash; report that lost capture and wait for the next slot. Exactly-once external HTTP is not claimed.

## Approaches

An adapter-only change cannot meet D15 isolation, state sharing and request attribution under the current executor. A cache inside the adapter or synthetic error reading would conceal failures and violate provenance. Replacing all adapter APIs with a new universal request pipeline is unnecessarily large. The chosen proposal adds optional capabilities, one request-scoped execution helper, grouped durable coordination, and feed-slot admission while preserving JPS and other legacy behavior. It costs focused core changes and integration tests; it does not pretend this is only a registry line.

## Adapter and narrow interfaces

New files: `packages/sources/src/adapters/apims.ts`, `apims-parser.ts`, `apims-discovery.ts`. Keep parsers pure and I/O behind `PollContext`. No runtime fixtures or `pilot/` imports. Runtime kind `apims`, `batch: 'all_bound'`, cadence `3600`, freshness `observed`, stale threshold `7200`, licence `{id:null,label:'No published terms found (5 Nov 2026)'}`. Add one real registry entry and one `adapter-apims` Terraform job, `*/15 * * * *`, `Asia/Kuala_Lumpur`, zero job retries. No new dependencies or credentials.

Proposed additive contract types in `packages/sources/src/contract.ts`:

```ts
interface RequiredObservation {
  metric: string
  observedAt: string
}
interface SourceFetchStep<Raw> {
  key: string
  fetch(ctx: PollContext): Promise<Raw>
}
interface GroupedBackfill<Raw> {
  groupByMeta: string
  requiredObservations(now: string): RequiredObservation[]
  steps(sources: Source[], anchor: string): SourceFetchStep<Raw>[]
}
// Additional optional SourceAdapter fields:
// parseMode?: 'per_source' // absent retains existing whole-group behavior
// groupedBackfill?: GroupedBackfill<Raw>
// latestSlot?: {
//   seconds: number
//   decode(body: Uint8Array): Raw
//   discover?(body: Uint8Array): DiscoveredSource[]
// }
```

Use `groupByMeta: 'state_id'`; accept only a positive safe-integer APIMS state ID. Generic core canonicalizes group identity from kind, meta key and JSON value, hashes it for object paths, and validates frozen source membership. Reject simultaneous legacy `backfill` and `groupedBackfill`. APIMS uses the new capability; JPS keeps legacy backfill unchanged. Required observations are the latest three actual 06:00 MYT instants at or before the plan clock, not arbitrary three values in a loose range.

`ApimsRaw` is a discriminated union: `{kind:'latest',body:unknown}` or `{kind:'history',body:unknown,through:string,stateId:number}`. `fetch` returns the latest wrapper after one `ctx.http`. Each history step returns its own wrapper from one GET, with the requested anchor. `parseApims(raw: ApimsRaw, sources: Source[]): ReadingInput<'apims'>[]` handles both forms. `discoverApims(body: unknown): DiscoveredSource[]` returns every valid map station, including station metadata, without filtering to the Commons. `createApimsAdapter(): SourceAdapter<ApimsRaw>` has no discovery transport options or global-fetch default. APIMS does not expose the legacy I/O-bearing `discover()` method; its canonical discovery interface is the pure `latestSlot.discover(body)` capability. Calling it outside a job still performs no network. Record this new adapter's discovery contract explicitly in #123/#79; do not describe a nonexistent APIMS `discover()` test as passing. Legacy JPS `discover()` and its transport remain unchanged. `catalogueSync` must select adapters with either `latestSlot.discover` or legacy `discover`, dispatch capability-first, and never fall through from a slot-aware adapter to the legacy network method. `adapterContracts` likewise uses the slot-aware decode/parse path first. The canonical registry remains one `[...existingAdapters, apims]` entry; no second discovery adapter or registration is introduced.

For each opt-in source, executor invokes the existing pure `parse(raw,[source])` independently, validates that source's typed rows, and catches `SchemaError` for that source only. A missing `data` array fails each source; one missing station fails just that station. Do not set the shared physical request's error for a source-local parse error, because `parseSourceResult` correctly refuses successful siblings attached to an errored physical request. Transport failures remain shared request failures. Error polls carry no readings. The returned error message names both external ID and source ID.

History steps are executed serially at one pinned MYT current hour, minus 24 hours, minus 48 hours. Parse each physical response independently; never assign all history to the final GET. Use one single-request `SourceExecutionResult` per step, each with its own durable operation/request ID, body hash and actual clocks. The group claim refers to all three immutable child results. This avoids changing existing multi-request aggregate digest semantics: current ingestion intentionally nulls digests for aggregate results, whereas these child results naturally retain the correct per-body digest.

Latest validates nonnegative safe-integer API (matching the declared CEL int metadata; no rounding/clamping), strict offset-less MYT timestamp round-trip, string `CLASS`/`PARAM_SYMBOL`, and unique matching station. Zero is valid. Malformed unbound rows do not poison valid bound stations. Duplicate/conflicting bound station entries fail that station. Discovery validates all coordinates/IDs/names/state IDs, rejects invalid catalogue rows before upsert, and sets source URL to the public map feed.

History requires `api_table_hourly`, validates station/state identity, nonnegative safe-integer API and timestamp, checks every retained time falls within `[through-24h, through]`, and rejects duplicate/conflicting station-hours. Absent or malformed required station data yields a station schema error for that physical response; do not attach valid rows to an error poll. An empty or truncated series is not invented into 25 values. Each complete captured response gives 25 inclusive rows, so the three windows overlap at two endpoints: persistence deduplicates those exact observation identities. No extra API metric or fabricated item key is needed. Historical class absence is omitted; `param` remains verbatim.

## Plan, coordination and persistence

The GCS poll plan gains a versioned grouped-backfill snapshot. At the 15-minute database batch, compute exact required-observation coverage and any prior state backfill poll, then group all active ownerless sources by the adapter's declared meta key. SQL lives only in `packages/db/src/sources/queries.ts`; generic query inputs include source kind, meta key/value, source IDs and required metric/timestamps. State-wide prior-poll lookup includes previously bound catalogue sources, not just the current tenant's visible group. Use system reads for public-source coordination and retain tenant checks for bindings/events. No scheduled adapter path queries Postgres.

The v2 plan has `backfillGroups` containing `{key, kind, sourceIds, anchor, requiredObservations, eligible}`. `eligible` means at least one member lacks required observations and no state member has any prior backfill poll. Reader supports v1 for legacy adapters only; APIMS grouped work fails explicitly until a v2 plan exists, rather than guessing eligibility. A completed durable state claim also suppresses HTTP before database ingestion catches up.

Add `runGroupedBackfillOnce(adapter, group, ports)` alongside the existing per-source helper. Group identity is stable across event/job races and later membership changes; the winning claim freezes membership, anchor and three child IDs before HTTP. Reserve outbox capacity for all child operations before admitting GETs. Persist and publish each actual step result before proceeding; a later timeout must not erase earlier good observations. Continue remaining distinct steps after a recorded transport/schema failure; these are the three scheduled attempts, not retries. Recover saved child bytes and stable identities without refetching. Preserve claim heartbeat/fencing and join in-flight renewal before completion. Generalize private outbox recovery metadata to a discriminated source/group identity plus step index; public Pub/Sub reference stays its existing four fields. Reject source membership, anchor, owner or result-path mismatches.

`source.bound` continues recording durable intent inside its transaction. For grouped adapters it schedules work against the next authoritative v2 plan, rather than querying or inventing global membership inside the tenant callback. The next batch exposes the binding; the event path and scheduled path then share the same group claim. Existing per-source JPS callback and immediate capture reuse remain intact. Latest all-bound polling must still include every active source even if a history group is running; history completion does not establish live freshness or remove a station from the current map fetch.

A generic latest-slot claim under `control/latest-slots/{kind}/{floor(now/slotSeconds)}` freezes all-bound membership and owns request/result identities. Use actual clock for slot admission even when `scheduledAt` is null; never invent Scheduler lag. The winning runner performs the normal all-bound capture and immutable publication. Duplicate scheduled invocations republish/recover the unchanged original result or report pending/lost capture, never allocate a second transport. Compare requested source IDs with frozen capture membership before returning a polling result: uncovered IDs are explicitly `not-covered`; do not append polls to the old result or synthesize new request IDs. Probes decode and parse that slot's raw bytes through `latestSlot.decode`; catalogue uses `latestSlot.discover` on the same bytes. With bound sources, catalogue/probes only inspect an existing current-slot capture; absence is explicit unavailability, not permission to initiate a competing GET. When no bound sources exist, catalogue may acquire a discovery-only slot through the same generic admission helper and execute the adapter's `fetch([], capturedContext)` once. That capture has no bound polls, is never sent to domain ingestion, and cannot later become a normal poll for newly bound sources. Probe execution never initiates HTTP or creates domain rows. Prior-slot or failed capture is unavailable, never served as current. Slot metadata is coordination, not a runtime reading cache.

The receipt policy deliberately keeps `recordSourceRequest`'s global `handleOnce('sources:request', physicalRequestId)` and all legacy receipts unchanged. Only replay of the exact original immutable operation is permitted. A successful operation receipt proves the polls actually persisted, not every station present in the provider body. If ingestion excludes a frozen member because its binding was removed/archived, a later rebind cannot recover that omitted poll by replaying the globally receipted request; it waits for a new physical capture in the next slot. Do not infer per-source ingestion success from request membership or a four-field result receipt. Cross-tenant fanout continues to use existing project-specific event receipts for actually stored polls; this does not authorize adding source polls to a receipted request. The availability cost is up to the remaining 15-minute slot plus the normal batch delay (and any real provider failure); first-slot discovery and probes may explicitly be unavailable. The budget stays one GET per slot, with no receipt migration, no per-source receipt scheme and no fabricated status, latency or request identity.

No schema migration for polls/readings is expected. Source ingestion already supports one errored source and successful siblings for a shared request, preserves source-purpose distinctions and capture fences, and assigns `receivedAt` on real write. Revalidate current bindings before fanout, retain RLS and append-only tests, and do not weaken `parseSourceResult` to accept false HTTP metadata. Raw hash, purpose, observed/transport/received clocks and request IDs are independently tested.
