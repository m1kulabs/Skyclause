## Polling and parsing

`jpsRain: SourceAdapter<unknown>` has `kind: 'jps_rain'`, `cadence: 300`, `freshness: 'observed'`, `batch: 'per_source'`, no `apiFamily`, and licence `{id: null, label: 'No published terms found (5 Nov 2026)'}`. `fetch` requires one source, validates a positive safe-integer `meta.jps_id`, and calls exactly one `ctx.http` GET to the fixed origin/path `https://infobanjirjpskl.water.gov.my/Rainfall/GetRainfallGraph/{id}` with `Accept: application/json`. Source metadata cannot replace the origin, add query parameters or cause a redirect. Source120 supplies the configured User-Agent, timeout, status capture and no retry. No data.gov.my family budget is consumed. `backfill(source, ctx)` delegates to the same fetch; it retrieves the full published seven-day window.

The pure `parseJpsRainfall(raw: unknown, source: Source): ReadingInput<'jps_rain'>[]` validates the object, exact `stationId === source.externalId`, `data` array and every row before returning. Each finite numeric `rf` becomes `metric: 'rain_5m_mm'`, `unit: 'mm'`, `valueJson: null`, the bound UUID `source.id` and UTC `observedAt`; do not store `dailyrf`. Match the existing `SOURCE_METRICS.jps_rain.rain_5m_mm` contract, already implemented by Source120; no schema migration is needed.

Port the pilot's strict timestamp logic without importing `pilot/`: accept `YYYY-MM-DDTHH:mm:ss` as MYT and its explicit `+08:00` spelling; validate calendar/time fields by round-tripping local components, then emit `Date.toISOString()`. Reject rollover dates, impossible times, other offsets, text/NaN/infinite rain and mismatched stations with `SchemaError`. Exact duplicate timestamp/value pairs collapse; conflicting values at one timestamp reject the whole payload. An empty `data` array remains valid. Do not invent missing rows or enforce complete coverage in this adapter. D12 interprets a value at T as (T−5 minutes, T]; coverage and rolling totals belong to #131.

## Discovery proven by portal requests

The portal does expose a station list, so the issue's static declared-station alternative is unnecessary. Recon in `121-recon/` captured this chain at `2026-11-10T12:15:28.616407+00:00`: `/Rainfall` loads `/Rainfall/Summary`; district 9 loads `/Rainfall/District/9`; that page requests `/Rainfall/LatestData/All`.

The latest-data response contains `table#Online-rainfalldata`, station rows with external station IDs, displayed station names and district text, and `/Rainfall/Station/{internalId}?districtId=0` links. It contains 49 unique internal IDs including `0232901RF` → `75`, `SG. KUYOH DI LRT BUKIT JALIL`, `Seputeh`. Parse those actual table rows; ignore historical/summarised rain cells and map-handler JavaScript. A focused browser-independent markup reader identifies the exact table/tbody, rows and cells, decodes character entities, and reads the fixed relative station path. It never executes HTML or JS and adds no HTML dependency. Validate nonempty names/districts/IDs, positive safe-integer internal IDs and consistent uniqueness of both IDs; malformed/empty/missing table or conflicting rows throws `SchemaError`. Do not silently drop malformed station rows or return a hard-coded catalogue. No request per unbound station is needed. The list does not publish state text: omit `meta.state` rather than inventing it; the genuine graph capture separately publishes state `KL`.

Entries are `{externalId, name, lat: null, lon: null, url: graphUrl, meta: {jps_id, district}}`; stale-after defaults to Source120's `2 * cadence = 600` seconds. Graph capture coordinates are null. Newer list HTML has map coordinates, but #121 explicitly accepts null coordinates; preserve nulls and archive the newer evidence without embedding numeric coordinates in adapter code. Future use of list coordinates is a product/contract decision, not a reason to type constants.

`SourceAdapter.discover()` has no context and Source120 calls it directly before its catalogue transaction. Export `createJpsRainAdapter({discoveryHttp?, userAgent?} = {})` for test transport/config injection and `jpsRain = createJpsRainAdapter()`. Resolve default transport (`globalThis.fetch`) and required `process.env.ADAPTER_USER_AGENT` only when executed `discover()` runs; an explicit nonempty factory User-Agent overrides the environment, and missing/blank configuration fails visibly. Discovery makes one fixed GET with `Accept: text/html`, configured User-Agent, manual redirects, a 60-second abort deadline and no retries (the station list took 31 s on 13 November 2026, so the first 20-second deadline never finished). Throw typed HTTP/network/timeout errors; parse shape errors are `SchemaError`. There is no apiFamily or family budget. Environment access stays at this server discovery boundary; pure parser and indicator modules import no process/Node/worker modules. This avoids changing Source120 composition or the discover signature.

Archive the response byte-for-byte as `docs/sources/infobanjirjpskl.water.gov.my/rainfall-latest-data-all-20261110T1215Z.html`, with a capture note documenting the chain and manifest hashes. Test against a byte-identical copy under the sources fixtures. Latest-data body: 228,937 bytes, SHA-256 `2bbe128c892708226c4419a57ce401e57d4933d1feab3e99ed0f5a8254a82d8b`. The original graph fixture is 127,043 bytes, SHA-256 `25cae3be496cff29b9925595d23fc63b7ddf9c1a4fb29e22b806b00d4ed3bd95`.

## Normal slot budget and contract probes

The final controller ruling treats the normal-poll budget strictly, including duplicate manual calls and concurrent jobs after initial backfill. `SourceAdapter.latestSlot?: {seconds: number; decode(body: Uint8Array): Raw; discover?(body: Uint8Array): DiscoveredSource[]}` is an opt-in contract addition. JPS declares 300 seconds and a pure graph JSON decoder. Its separate HTML `discover()` endpoint remains unchanged. This implementation supports per-source slot admission; all-bound and discovery-only use of this metadata belongs to #123.

For an opted-in per-source adapter, the runner creates `control/slots/{kind}/{normalizedSourceUuid}/{actualClockBucketStartMs}.json` with generation zero. The immutable claim contains the original operation ID and genuinely supplied scheduledAt, including null. The actual UTC clock bucket controls admission; it never becomes Scheduler metadata. Only the claim creator may reserve outbox capacity and execute the adapter. At the physical HTTP boundary the private context checks that the clock remains in the claimed half-open interval and that this context has not already started transport. Delayed GCS writes, outbox reservation, adapter work or family admission cannot carry permission into a later bucket. A denied start retains null HTTP status, null transport start and a visible typed failure.

Normal bytes are saved at the existing immutable delivery path before publication. Redelivery and publication repair retain their original operation/request IDs, source association, purpose, scheduledAt, body and hash. A consumed claim without durable bytes never refetches within its bucket; a duplicate reports running (or lost after the boundary). A separate next-bucket invocation may claim a new attempt. Missing outbox results remain visible under the existing reservation expiry and hard-cap rules; neither capacity nor claims are silently reset. Costs include GCS coordination and retained claims, possible lost slots after an ambiguous crash, and the existing operational intervention required for unresolved reservations. Backfill lease/recovery rules remain unchanged, including their documented crash-before-save limitation and freshness semantics.

Opted-in contract probes only read and decode/parse a successful current-slot capture, including a completed first-bind backfill captured in that same bucket. They make no graph request, publish no result and write no domain or coordination state. An absent, running, failed, previous-slot or future capture reports explicit unavailability; it does not use stale success. Legacy adapters retain their existing probe path. Saved backfill reuse preserves its original purpose and cannot establish live polling freshness. Clock rollback cannot justify reusing a future normal capture.

Operators should inspect `source.slot.unavailable`, source-request transport/status fields and the existing pending-results repair errors. Wait for an independently admitted next slot when bytes were lost; do not delete claims or replay HTTP to fill the gap. The acceptance count must report missing slots, not manufacture 288 successful polls. Parent-owned contract-labelled PR and #79/#121 alignment are required before landing this public metadata addition.
