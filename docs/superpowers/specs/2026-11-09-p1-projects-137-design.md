# P1 projects core design

Implement #137 against #79 with the existing tenant transaction and operation registry. Admins create an empty project, update its owned settings, archive/restore it and read authorised projects and summaries. Creation atomically writes both pack configurations and both immutable default sheet versions; it never inserts windows, sources or readings. Sky follows selection; Crowd starts disabled until #138 binds prerequisites. Call-in-force precedence follows D3, not merely newest timestamp.

The user authorized autonomous core delivery, isolated simulations, reviewed merges and closure, retaining material live checks separately. Their parallel-small-task instruction is implemented with a separate worktree and one writer for this issue; the ongoing #131 writer edits another worktree. Shared CI and main integration remain serialized. This package already has canonicalHash on main, so project bootstrap does not depend on the unmerged engine implementation.

Keep DB queries in packages/db, services in packages/api with {principal,tx}, and thin registry handlers. Correct only request/response contract drift required by the issue and actual nullable DB fields; never fabricate schedule, camera hours or semester dates. A reserved slug must reach its specific problem response. Optional defaults are configuration, never sample business data. Settings outside #137 stay with their owner. Use declared package entrypoints for both JSON defaults: narrowly add JSON subpath exports in packages/clauses/package.json if required, without changing engine source or signatures.

Tests exercise real Postgres rollback, bootstrap counts/hash/content, idempotency, visibility/permissions, public-page permission and in-force summaries. No application UI, live email, shared-pilot setup or other owner's evaluator/pollers are implemented here. Downstream UI/run integration acceptance stays with the existing owning issues; source closure requires real automated evidence and merged code.
