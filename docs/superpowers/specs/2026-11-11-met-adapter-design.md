## Approach and boundaries

Chosen: two small adapters and pure parsers using the stable `SourceAdapter`/`PollContext` interface, with one narrow composition binding for budgeted discovery. Keep the existing runner and database persistence. The alternative of global `fetch` inside discovery bypasses shared admission. A universal provider framework or dependence on APIMS's pending optional parsing/grouped-backfill capabilities adds unrelated coupling. Neither is needed for two single-request MET adapters.

The feature comprises parsing and metadata, real registry/cadence/discovery wiring, and real PostgreSQL integration verification. No new dependencies, credentials, database tables or migrations are expected. SQL remains exclusively in `packages/db` if a demonstrated gap later requires any. Published migrations are immutable. No `pilot/` import, fixture import, source fallback, typed coordinate, or runtime test registry is allowed.

Ownership stays narrow: the parent has included the necessary surgical #131 warning reducer correction in this MET feature. #133 owns the source-state/history context wiring; #138 and UI owners retain binding/history screens. No parser value is falsified to accommodate the old engine. The engine correction and its tests belong in Task 3; the #133 loader seam is documented explicitly.

## Contracts and conflicts

1. **Discovery context:** `discover?(): Promise<DiscoveredSource[]>` takes no context. Keep this signature. `createMetForecastAdapter({discoveryHttp})` closes over an injected `PollContext['http']`; its `discover()` rejects with `SchemaError` before any network when the dependency is missing. The canonical registry adapter still supports polling. At the worker composition root, replace just that instance with the configured factory instance, supplying HTTP from `createPollContext` with family `datagovmy-weather`, the same GCS store, clock, request-ID source and user agent. Use that configured adapter array consistently for jobs and ingestion. This is composition, not a new generic discovery framework. No adapter-kind branch belongs in generic execution, admission or persistence. A discovery request has no bound sources and writes no domain poll/reading rows; it still consumes family admission, captures physical request metadata, drains outstanding work and logs the result. Its failure preserves the prior catalogue through existing transaction ordering. Existing JPS behavior and pending APIMS capabilities remain untouched.
2. **Actual warning reducer mismatch:** baseline `packages/clauses/src/snapshot.ts:449` hardcodes Kuala Lumpur, reads flattened title properties, ignores `excluded`, substitutes observed time for missing start and accepts a null end indefinitely. `evaluate.ts:315` also treats null warning end as infinity. #122 requires project warning-area terms and both valid bounds. Implement the parent-authorized narrow #131 correction within this feature before claiming full SIG-4. Do not flatten or rewrite the raw record, force `value=0` to conceal invalid validity, add made-up area matches, or copy `TEST_REGISTRY` into runtime. The fresh integration test must expose these failures if the correction is absent.
3. **Project area terms seam:** `ReadingHistory` contains sources/meta/readings but no project configuration, while the warning feed is a shared singleton. Add the smallest explicit context seam, `ReadingHistory.warningAreaTerms?: string[]`, without changing the `snapshotAt` function signature. The engine uses only the supplied project terms; absent/empty terms match nothing and never fall back to Kuala Lumpur. #133/history owner must copy the actual `project.warningAreaTerms` into that project-scoped history after its tenant-scoped project read. No project terms go on the shared global source or persisted `excluded` field. The parent aligns this additive type field in #79 before landing. The loader is not claimed implemented by this plan.
4. **Successful empty warning feed:** a valid top-level `[]` is a successful no-reading result, not a feed error and not a manufactured No Advisory reading. It reaches the existing runner as `unchanged`. A timeout, HTTP failure, HTML or JSON error object reaches an error poll with no readings. The successful poll updates polled freshness without inventing a withdrawal/tombstone for previously captured warnings. A previously captured warning remains eligible only over its explicit published validity interval and matching project terms, even after a successful empty feed. Whether disappearance or No Advisory supersedes an otherwise still-valid warning is IMPORTANT unverified provider semantics, absent from the official docs inspected; the parent records a live follow-up ticket and does not add membership schema or claim empty feeds always clear warnings. The possible cost is a still-valid retained warning until its stated expiry. Do not change source default `status: unknown` into healthy.
5. **Unfiltered size/cap evidence:** implementation must inspect a genuine unfiltered response before claiming discovery acceptance. The docs do not establish a total-count/pagination mechanism; do not invent `offset`, a fixed limit, or catalogue coordinates. Persist only the distinct published identities returned by the verified response and report any completeness limit. If the API proves truncated, resolve the smallest documented query policy before landing rather than silently asserting full discovery.

The first conflict costs a small worker composition change and integration test. The reducer fix is included; the area-term loader seam costs coordinated #133 owner work and is not silently an adapter implementation. Missing that wiring limits production project-specific correctness. The final evidence item costs one budgeted unfiltered GET plus its capture/provenance, not daily extra limit probes. No contract or issue edit occurs in this planning task; the parent session handles required contract alignment before landing.

## Parsing and metadata

Create `met-warning.ts`, `met-warning-parser.ts`, `met-forecast.ts`, `met-forecast-parser.ts`, and `met-forecast-gloss.ts` under `packages/sources/src/adapters/`. Keep I/O in adapter fetch/discover closures and parsers pure. Both adapters use `apiFamily: 'datagovmy-weather'`, `freshness: 'polled'`, licence `{id:'CC-BY-4.0',label:'MET Malaysia via data.gov.my, CC BY 4.0'}`. Warnings use `batch:'all_bound'`; forecast uses `batch:'per_source'`. No MET backfill is requested or needed: first regular fetch supplies the currently published warning/forecast data.

Warning singleton discovery returns external ID `met-warnings`, name `MET Malaysia warnings`, published warning URL and null coordinates. Fetch once for the entire unique bound warning cohort from `https://api.data.gov.my/weather/warning/`. Validate the singleton identity. Empty sources are never fetched by the runner; malformed/multiple different singleton identities are rejected.

`parseMetWarnings(raw: unknown, sources: Source[]): ReadingInput<'met_warning'>[]` requires a top-level array and all published required English/Malay fields with their actual nullable instructions/validity. Validate the raw object without replacing it with a stripping Zod result; preserve extra fields, nested `warning_issue`, Unicode, case, spacing and line breaks. Reject missing fields and invalid types. Offset-less issue/validity timestamps are MYT; parse with explicit `+08:00` and round-trip validation, never host timezone or permissive rollover. Null validity remains null; non-null malformed or inverted validity is a schema error.

Each warning has metric `warning`, unit null, value null, `observedAt` equal to normalized `warning_issue.issued`, `valueText` equal to published `text_en`, and `itemKey` exactly `${title_en}|${valid_from}` (JavaScript null spelling `null` for the captured No Advisory). JSON is the original row plus `valid_from_utc`, `valid_to_utc`, and `excluded`. Exact English title `No Advisory` or a title containing `Rough Seas` is excluded, using case-insensitive comparisons only for classification and retaining raw titles. Identical duplicate observation identities may collapse; conflicting duplicates fail the feed. No expiry filtering occurs at ingestion: retain the source's listed expired and future records.

`isMetWarningInForce(value, span: {from:string;to:string}, areaTerms: readonly string[]): boolean` is a pure contract predicate for #122 tests: false when excluded, either normalized validity bound is null, no nonempty configured area term matches either English/Malay text, or intervals do not overlap. Otherwise use inclusive `valid_from <= span.to && valid_to >= span.from`. Do not translate or infer geography. The same rule must be exercised by the actual #131 correction in Task 3; the parser predicate alone is not end-to-end proof.

`metForecastUrl(source: Source): string` uses the trailing-slash path and the discovered source name, URL encoded, as `contains={name}@location__location_name`. `parseMetForecast(raw: unknown, sources: Source[]): ReadingInput<'met_forecast'>[]` requires exactly one bound forecast source; retain only `location.location_id === source.externalId`. A malformed matching row or no matching rows is a schema error. Other locations cannot supply missing data. Validate the full matched row: nonempty location ID/name, real local date, strings for morning/afternoon/night/summary forecasts and summary time, finite integer temperatures. Do not require exactly seven rows or fill absent days: preserve the actual published day set; #131 owns the missing-today freshness check. Collapse exact duplicate days; conflicting duplicate days fail the source. Discovery validates every catalogue row instead of ignoring unbound malformed entries.

Forecast metric is `forecast_day`, unit null, `observedAt` the date's midnight MYT, `itemKey` the exact date, `valueText` the raw `afternoon_forecast`, and numeric value 1 iff that field contains `Ribut petir` case-insensitively, otherwise 0. JSON is the whole raw row plus `gloss_en`, a per-field string map. Existing database comparison appends only changed days. Strengthen the existing forecast value schema to require the complete published matched row while retaining extras. Do not introduce unrelated metric or licence changes.

The committed gloss table uses exact known Malay phrases after case-folding for lookup only. Start with the official vocabulary and DESIGN voice list, plus actual archive phrases `Tiada Hujan`, `Mendung`, `Hujan di beberapa tempat`, `Hujan di kebanyakan tempat`, `Ribut petir`, `Ribut petir di beberapa tempat`, `Ribut petir di kebanyakan tempat`, `Pagi dan Petang`, `Petang dan Malam`, and `Sepanjang Hari`. Use clear glosses such as “Cloudy”, “Rain in most places”, and “Thunderstorms in most places” for the capture-only phrases; a Malay reader must review the table before merge. Unknown phrases omit that gloss key; they never trigger machine translation, English defaults or replacement of the source text. `gloss_en` explicitly distinguishes derived glosses from originals; UI language rendering belongs to its owner.

Add `metWarningIndicators` and `metForecastIndicators` in browser-safe `src/indicators/index.ts`, typed as `IndicatorDefinition[]` with `satisfies IndicatorDefinition[]`:

| Name                              | CEL type | Unit         | Scope    | Kind           |
| --------------------------------- | -------- | ------------ | -------- | -------------- |
| `site.met_warning_in_force`       | `bool`   | empty string | `site`   | `met_warning`  |
| `w.met_warning_in_force`          | `bool`   | empty string | `window` | `met_warning`  |
| `site.met_afternoon_thunderstorm` | `bool`   | empty string | `site`   | `met_forecast` |

Append both arrays to the real exported `indicators` aggregate, and assign them to their adapter metadata. These are the concrete names/types already exercised by the engine's existing tests; runtime must not import test helpers. Use the resulting actual aggregate in the default Sky check/evaluation integration test. Baseline full defaults also require APIMS and camera metadata absent from this registry: prove the actual Storm watch default clause now, require no unknown MET-name diagnostics on the full default, and claim full-default success only after those owners supply their real metadata. Do not invent `met_warning_in_force` without its scope prefix, or add reducers to this package.

## Discovery and execution

Forecast `discover()` performs one unfiltered `https://api.data.gov.my/weather/forecast/` GET in the existing daily catalogue job, inside the same weather-family admission as polls and contract probes. Parse distinct published location IDs and their published names; conflicting names for one ID fail discovery. Emit null lat/lon and metadata with the published location name, never coordinates or a fixed city list. An empty or malformed catalogue fails before its database upsert; it cannot clear or replace known sources with guessed data.

Register `metWarning` and `metForecast` in the canonical adapter registry alongside existing adapters, with named factory exports needed by composition. Add `infra/environments/production/met-weather.tf` containing two real job modules, names `adapter-met-warning` and `adapter-met-forecast`, args `["job","adapter","met_warning"]` / `["job","adapter","met_forecast"]`, schedules `*/10 * * * *` / `0 */6 * * *`, timezone `Asia/Kuala_Lumpur`, and `max_retries = 0`. Match JPS's existing jobs service account, invoker, env, secrets and dependencies. The source runner is already registered in the worker; add no duplicate worker part. No apply/deploy during implementation without the parent session's authorization.

Adapters call `ctx.http` once per fetch and do not add a second `budget.take` or their own sleep/retry loop. The budgeted discovery closure does the same through its captured context. Keep 301/302 visible errors; never follow HTML redirects. A 429 is one error poll and waits for the next scheduled slot. Preserve actual status and latency; transport/admission failures retain null HTTP status. Forecast sources remain independent per-source requests, so one failed location does not poison siblings. Warnings share one physical request and fan out a poll to each bound singleton source identity. Distinct tenant bindings share the same public source and never multiply network requests.

Normal scheduled request cost is `144 + 4L` per day for `L` bound forecast identities, plus one daily unfiltered discovery and the existing probe request per bound adapter. For one forecast source and both probes this is 151 daily weather requests, before failures/crash repeats; average request load does not prove burst capacity. Four-reservation/80-second admission can reject aligned forecasts/probes under saturation; record those errors, with no hidden retry. Producer jobs use GCS only; Postgres wakes for the existing 15-minute ingestion/catalogue work, not per poll.
