It preserves the teammate's single-window list/create work and the existing tenant, event, ledger and worker boundaries. Baseline: `f69fee4ff98acdb41e277af6958079ea9e2c7073`.

## Approach and scope

Build small pure calendar functions inside `packages/api/src/services/windows/`, persistence/mutation functions inside `packages/db/src/windows/`, route adapters inside the existing windows owner, and a `windows` WorkerPart. Existing conditions-calendar output in `apps/worker/src/ics/` and `packages/db/src/ics/` remains its own owner; do not conflate imported schedules with outbound conditions calendars.

Alternatives were a separate calendar package/framework or handwritten ICS parsing. Neither is needed: the repository already locks the maintained `ical.js` parser and has the required infrastructure. Promote the existing API dev dependency `ical.js: "2.2.1"` to runtime. The worker imports the API's `./windows` service export, so it needs no second parser implementation.

No frontend, seed, public-data substitute, production mutation, scheduler or minute-tick database work. No permissive guest/share fallback. Existing migrations are immutable; add a new migration after the teammate merge.

## Interfaces and ownership

The unpublished teammate branch cannot establish actual names yet. Request the following **semantics** from its merged services; use its actual names instead of adding a parallel abstraction. Proposed names if none exist:

- `authorizeWindowProject(ctx: ServiceContext, can: Can, projectId: string, statement: 'project.view' | 'window.declare'): Promise<ProjectRow>`: unscoped denial before lookup, tenant lookup plus target-scoped canonical Can, guest Commons restriction, foreign/hidden 404.
- `validateWindowFields(fields: WindowFields, now: Date): FieldIssue[]`: plain WIN-8 checks shared by create/update/import. `FieldIssue = { pointer: string; detail: string }`; API maps these into `{in:'body', pointer, detail}`.
- `windowView(tx: Tx, row: WindowRow): Promise<WindowView>`: exactly the teammate's serialization, latest per-pack calls and shadow rules; lifecycle services never invent another read shape.
- `windowProvenance(principal: Principal): {declaredBy: string; via: WindowVia; shareLinkId: string | null; guest: boolean}`: one source for principal-derived attributes, preserved on edits.

Our new DB `writeWindowChange` is the one mutation primitive used by edit/cancel and import/extension. It receives an authorized tenant transaction, validated fields, mutation time and optional immutable calendar metadata; it performs the actual change, event and cancellation ledger atomically. Reuse an equivalent teammate primitive if it exists. A genuine no-op emits nothing.

API functions take `ServiceContext` and `{can, now}`. Worker functions never call canonical Can with `system` and pretend that is a user grant: they operate on persisted, tenant-owned declarations after their own authoritative eligibility checks. Shared pure parser/recurrence functions have no DB, global timezone registration or transport access.

## Recurrence and edits

`frequency` is weekly; weekday names retain the existing wire enum. Exactly one positive integer `count` or real calendar `until` date is required, duplicate weekdays fail, unknown fields fail at every object level, and `skip_dates` are real dates. `until` is inclusive. `count` counts scheduled dates before skips. The first anchor date must be one of the chosen weekdays; reject `/recurrence/days_of_week` otherwise instead of silently changing the declared first occurrence.

Enumerate civil dates, then resolve local start/end through PostgreSQL's zone rules in a DB helper using the existing `AT TIME ZONE` pattern. Preserve seconds/fractions and overnight end-day offset. Validate the zone against PostgreSQL and `Intl`, because evaluator local-calendar extraction uses `Intl`. Use UTC date arithmetic only for date labels, never to mean 24 elapsed hours in a local zone. Nonexistent local times fail round-trip validation; ambiguous times follow PostgreSQL's existing standard-time interpretation. Resolve/validate every materialized occurrence before writing any of them.

Materialize only starts in `[now, now + 90 * 86400000]`. Keep the original rule/anchor/count so each daily extension uses the same schedule rather than restarting count or adding replacements for skips. A cancelled occurrence remains a tombstone keyed by its original schedule date and cannot reappear. A local edit marks that occurrence as overridden. An unchanged schedule date retains its ID; a changed recurrence membership cancels removed future dates and creates newly eligible dates, preserving historical rows/calls.

Proposed scope ruling: occurrence edit affects only that row; series edit updates its template and all not-yet-started members, including explicit occurrence overrides, then reconciles future membership. Already started rows remain unchanged. Changing series start/end takes the selected occurrence's new local clock and date shift as the template change, not its absolute UTC instant for every member. Series cancellation stops generation and cancels all not-yet-started members. An explicit occurrence cancellation may record historical withdrawal. WIN-8 continues to prohibit past creation and time edits; this cancellation is a new audited withdrawal at the current time, retaining the historical starts/ends and every call, rather than rewriting the past. Reject an occurrence-level `recurrence` patch, an empty patch, edits to cancelled rows, and a series scope on a non-series manual window with field/state errors. A repeated cancellation is a no-op.

The existing create route still returns one `WindowView`: return the earliest materialized occurrence of a successful recurring declaration, with its `series_id` and recurrence. If every candidate is skipped or no candidate falls in the allowed horizon, return 422 `/recurrence`; do not create an empty unusable series. Native series creation enters the teammate's create handler only through a recurrence branch, preserving its single-window path and idempotency middleware.

## ICS normalization and reconciliation

Use `ICAL.parse`, `Component`, `Event`, `Event.iterator()` and `getOccurrenceDetails()`. Iterate from the original DTSTART, bounded by the requested horizon and work limits; never restart DTSTART at the current date because COUNT and BYDAY depend on the original anchor. Relate exceptions by UID before expansion, honor EXDATE/RDATE, and use the original recurrence identity even if an exception moves DTSTART. These APIs are documented by the parser's [official event API](https://kewisch.github.io/ical.js/api/ICAL.Event.html) and [recurrence guide](https://github.com/kewisch/ical.js/wiki/Common-Use-Cases).

Persist a normalized calendar document containing only needed properties: UID, DTSTART, DTEND/DURATION, SUMMARY, RRULE/RDATE/EXDATE, RECURRENCE-ID, STATUS and referenced VTIMEZONE definitions. Do not store attendees, email addresses, descriptions, locations or attachments just because they appeared in the upload. UID is a source identity, never copied into audit/ledger body or logs. Missing title fails the individual event; no invented title. Imported `kind` is the request's kind, default `class` as the ticket explicitly directs. Persist `window.tz` as the project zone; source timezone information remains in the normalized calendar definition.

Resolve UTC directly, source-provided VTIMEZONE from that calendar's component tree, and floating times in the project zone through the DB conversion seam. Require a source VTIMEZONE for a non-UTC TZID; report the affected event/UID as skipped when it is missing, even if its identifier looks like an IANA name. This explicit compatibility limit avoids silently interpreting an unresolved TZID as floating/UTC or adding another timezone/recurrence implementation. Native recurrence still supports validated IANA zones through PostgreSQL. Never register feed-defined zones in the process-global TimezoneService: two tenants can use the same TZID differently. The pinned source shows [component-local timezone lookup](https://raw.githubusercontent.com/kewisch/ical.js/v2.2.1/lib/ical/component.js) and [TZID resolution behavior](https://raw.githubusercontent.com/kewisch/ical.js/v2.2.1/lib/ical/time.js).

Identity is `(feed_id, UID, RECURRENCE-ID)`. For a recurring occurrence, use its original source recurrence frame: normalized UTC Z, floating civil timestamp, or embedded TZID plus civil timestamp; normalize exceptions against the master frame. Project-zone changes must not change source identity. For standalone events use an explicit empty identity string, not mutable DTSTART. Missing, duplicate or unrepresentable identities are malformed-document errors. UID and recurrence identity are each limited to 1024 UTF-8 bytes before persistence, preventing composite btree-key overflow without truncation. Persist the original identity separately from overridden current times. One source recurring UID gets one series row; standalone imports have no series. Source RRULE changes reconcile that UID's occurrence set. Source cancellation, disappearance and EXDATE removal cancel existing upcoming source-managed rows; disappearance is assessed only inside the successfully parsed reconciliation horizon. An event outside the current horizon is not proof that an older imported event was deleted. Invalid/skipped identities protect existing rows from destructive “missing event” cancellation, and malformed documents apply no diff.

Local occurrence overrides and cancellations survive source refreshes. A later genuine source restoration may clear a source-created cancellation on the same non-overridden row, retaining its ID and prior ledger history; it cannot clear a local cancellation. Manual cancellation marks local override, whereas source cancellation does not. Series field overrides apply to subsequent source occurrences; source membership/recurrence remains authoritative. An imported-series recurrence patch returns 422 `/recurrence`. A valid source change updates unoverridden title/times/kind as applicable; events carry `times_changed` only when start or end changes. No-op bodies emit no events. Removing a feed stops refresh and cancels upcoming imported rows through the same mutation primitive, retaining referenced rows/calls.

Limits proposed for parent approval: 5 MiB UTF-8 input, 10,000 VEVENTs, 100,000 iterator steps including skipped historical iterations, 10,000 output occurrences and 20,000 changed rows per reconciliation. Exceeding a limit rejects the entire import/refresh without partial destructive application. All-day and other individual WIN-8 failures appear as `{uid, recurrence_id, pointer, detail}` in `skipped`; no handwritten production calendars.

The bounded initial parser reports/protects the whole UID for RANGE exceptions, including THISANDFUTURE, although the library supports its core shift. Correct range horizon/cancellation handling is outside this initial supported subset. Unsupported EXRULE rejects the document. No silently unchanged partial series is emitted.

Admitted event RRULE selectors are unfiltered SECONDLY/MINUTELY/HOURLY/DAILY/MONTHLY/YEARLY, or WEEKLY with only ordinary non-ordinal BYDAY and WKST. COUNT/UNTIL and a positive integer INTERVAL remain supported. Other event selector combinations protect the UID before constructing an iterator; this deliberately rejects some valid calendars whose internal contracting/constructor scans cannot be bounded. Source observance DTSTART must be a floating date-time; source rules use YEARLY at that clock, with BYMONTH, ordinary/first-through-fourth/last BYDAY, or nonzero BYMONTHDAY within -28..28; BYDAY and BYMONTHDAY cannot intersect. If a source rule selects months without an explicit day selector, the DTSTART day must exist in every selected month in every year. Stored duplicate selectors reject; the text parser's own selector deduplication remains effective. These admitted forms guarantee nonempty source constructor candidates without a second recurrence engine.

| Frequency | Maximum INTERVAL |
| --------- | ---------------: |
| SECONDLY  |       31,622,400 |
| MINUTELY  |          527,040 |
| HOURLY    |            8,784 |
| DAILY     |              366 |
| WEEKLY    |               52 |
| MONTHLY   |               12 |
| YEARLY    |                1 |

These bounds cap each civil normalization advance at a leap-year-sized increment. DURATION must be finite, nonnegative and at most 43,200 nominal seconds before hydration; positive civil days/weeks are outside this supported WIN-8 subset. Explicit DTEND preserves its supplied endpoints and establishes the exact elapsed duration reused by a recurring master. Supported DURATION hours/minutes/seconds likewise add elapsed time, so a source DST crossing cannot stretch a window. [RFC 5545 §3.3.6](https://www.rfc-editor.org/rfc/rfc5545#section-3.3.6) distinguishes those accurate units from nominal days/weeks; [§3.8.5.3](https://www.rfc-editor.org/rfc/rfc5545#section-3.8.5.3) preserves DTEND-derived exact duration across recurrences. A two-day raw civil endpoint guard bounds the library's intermediate arithmetic before elapsed WIN-8 checks. Calendars relying on otherwise valid longer nominal durations, larger intervals or unproved selector intersections are explicitly refused/protected, never truncated.

Source offsets must be exactly representable by pinned 2.2.1: whole minutes between -12:00 and +14:00 inclusive; nonzero seconds or wrapped offsets reject the source definition. Source observance RDATE lists normalize into equivalent single-value properties and include DTSTART's onset, preserving transitions the pinned hydrator would otherwise lose. Source timestamps before known onset coverage protect their UID, and recurrence-frame conversions must round-trip the original instant exactly; an ambiguous/unrepresentable exception identity rejects the document. This avoids the library's zero-offset fallback and lossy fold conversions.

The shared 100,000 work ceiling includes raw RDATE preprocessing, logical event candidates (including historical/excluded positions), and source-transition preflight candidates. Event RDATE values are canonicalized to the master's frame, sorted and deduplicated into one property before the library's ordered insertion; semantically distinct supported values remain intact. Source preflight uses public Recur iterators, the pinned UTC-UNTIL adjustment, and the exact library minimum/current year plus EXTRA_COVERAGE. Hydration replays only verified work, with component-local zones prefilled through that verified year; it is not claimed to expose private iteration counters. Farther source years repeat preflight before offset lookup. Whole-document budget overflow still applies no diff.

## Durable storage

Extend the existing three owned tables; no generic workflow engine or separate manifest table:

| Table           | Additions                                                                                                                                                                                                                                                                                                                                  |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `window_series` | Nullable versioned `definition` JSON holding original anchor, end-day offset, title/kind/tz and principal provenance; nullable `ics_feed_id`/`ics_uid` for imported series; `checked_on` local date; `cancelled_at`; nullable `last_error`; existing rule/local times/materialised-until remain. Unique imported `(ics_feed_id, ics_uid)`. |
| `window`        | Nullable `series_occurrence_date` for native identity, nullable `ics_uid`/`ics_recurrence_id` for source identity, `local_override` boolean default false. Unique `(series_id, series_occurrence_date)` and `(ics_feed_id, ics_uid, ics_recurrence_id)` when populated.                                                                    |
| `ics_feed`      | `kind` default class; nullable normalized `document`; `last_attempt_at`, `next_refresh_at`, `refresh_claim` UUID, `last_error`, `deleted_at`; `skipped` JSON array; `materialised_until`; retained existing etag/last-modified/refreshed-at. Source grants/provenance in a versioned JSON object with IDs only, never credentials.         |

Use same-organisation foreign keys and tenant policies for additions. Additional CHECKs ensure paired ICS identities and well-shaped new native/imported identities. New fields are nullable where legacy rows lack evidence. Do not guess a template, identity, actor or source body for legacy rows: an unprovable legacy series/feed is reported unavailable and excluded from unattended mutation until genuinely reconciled. Migration sequence is determined after rebase (baseline highest number is 0049); never rewrite an applied migration or snapshot.

Locks: lock feed first (if applicable), then series, then affected windows in UUID order. Individual manual edits take the same applicable parent locks before row lock. Recheck state after locking. All changes/events/ledger entries commit together. Unique identities prevent concurrent extension/import duplication. Updating a definition invalidates any pending old refresh claim before it can overwrite local changes.

## Authorization and cancellation

Reuse canonical Can, `withTenant`, scoped project lookup and teammate provenance helpers. Forbidden actors receive uniform 403 before target lookup; authorized callers get 404 for foreign/hidden rows, consistent with the #79/#138 amendment. Viewers may read but cannot mutate. Guest Commons and own-window restrictions come from the real guest policy. Reauthorize direct service entry points as well as routes. No bare caller-provided org/project/actor fields are trusted.

For each newly inserted guest/share occurrence, call real `BudgetGate.consume(tx, principal, 'window')` in the same transaction; refusal rolls back the complete series/import and returns 429 `budget-exhausted`, `resets_at`, and `Retry-After = max(1, ceil((reset-now)/1000))`. Apply real guest title/time/expiry/hash policy before storage. The missing #181 implementation and unattended grant policy block activation of those principals' series/import paths; they must not be replaced with runtime test doubles or success defaults. Tests can inject isolated doubles. Do not add an invented port signature for `applyGuestWindowPolicy`; integrate its owner's actual typed seam once settled.

Cancellation sets `cancelled_at` once. If any call on that row is `sent`, append exactly one `window_cancelled` ledger entry for that transition, with `refs: {window_id}` and `body: {actor_type, actor_id, cancelled_at}`; no title, UID, email, name or token. The actor follows existing audit identity conventions: session account ID, API key ID, OAuth client ID, guest-token ID, share-link ID, or system job name for refresh. Preserve every call and all bundle state. The real `appendLedger` runs in the same transaction and an error rolls back cancellation/events. Repetition emits no second ledger row. The policy must prohibit a guest window from producing a public ledger entry, consistent with GST-5.

## Due checks and event integration

Add one `windows` WorkerPart with `batch: {'windows-due': handler}` and its one-line registry entry; no `ticks`, task queue or Scheduler job. Under `withSystem`, enumerate project/org pairs only (other T tables are invisible without tenant scope). Then serial `withTenant({orgId, principal: systemPrincipal('windows-due')})` calls inspect due series/feeds. Preserve `shareSystemConnection` rules; no nested withTenant inside withSystem and no unawaited work.

Native series: once per project-local date, extend to the current 90-day horizon and persist checked date/materialised frontier atomically. Retry failed work at a later existing batch, recording/logging the actual error; do not mark it successfully extended.

URL creation stays inside the existing authenticated `ServiceContext.tx`: authorize, validate the URL with `assertPublicUrl(url,{https:true})`, and insert a feed with `next_refresh_at=now`, null `refreshed_at`/`last_attempt_at`/document, and no windows. The initial guard may resolve DNS inside that request transaction; no calendar HTTP request runs there. Return 201 for the registered resource with `status: pending`. Existing idempotency middleware replays that original creation response; callers read get/list for subsequent status. File imports parse/expand and apply immediately in the same request Tx, binding the local-span resolver to that Tx, and perform no HTTP. No new global idempotency mechanism is introduced.

Expose optional `status: pending|ready|error|removed` derived from actual state: removed when deleted; error when last_error exists; ready after a successful import/check; pending otherwise. `last_attempt_at` is null until the worker claims an attempt, then records that claim time; `refreshed_at` is null until actual success. No queued registration claims that parsing or window creation succeeded. The present UI always announces “Calendar imported.” after any 201 and ignores the body; @kymil4 must distinguish pending URL registration from file-import completion. Keep 201 because a feed resource exists, amend its contract description, and explicitly move remote-content/redirect failures to feed status after registration.

URL feeds: claim under row lock if `next_refresh_at <= now`, storing a new UUID claim and `next_refresh_at = now + 1 hour`. Commit the claim transaction before guarded HTTP. After HTTP, enter one fresh tenant apply transaction, recheck that the claim matches and the feed is active, then parse/expand/diff. Bind `resolveLocalSpan = span => resolveWindowLocalSpan(tx, span)` to this same apply Tx for all occurrences; do not open a connection or transaction per occurrence. No HTTP occurs inside the apply Tx. A crashed attempt becomes due in one hour; concurrent batches cannot run the same claim; late results cannot overwrite a later claim or a deleted feed. Each failed attempt records its real error without changing source validators, successful source document or windows. Reads expose failure instead of claiming the old document is a successful refresh. File feeds never perform HTTP; their persisted authoritative recurrence definition may extend daily without re-importing the source.

Fetch calls `assertPublicUrl(url, {https:true})`, then `safeFetch(url, {https:true, redirects:'follow', maxRedirects:3, timeoutMs:10000, maxBytes:5242880, headers})`. Use If-None-Match when an ETag exists, otherwise If-Modified-Since. 304 advances successful check time and may extend the confirmed unchanged definition's horizon; it never cancels everything because it has no body. Successful 200 parses in the fresh apply transaction before any diff and atomically stores validators/document/check time plus changes. Unsafe URLs, including a redirect to private/loopback/link-local/metadata, map explicitly from `UnsafeUrlError` to 422 `unsafe-url` during creation preflight; the generic API error mapper does not do that today. A worker-time unsafe redirect is a stored `last_error` with code `unsafe-url`, not a retroactive HTTP response for the already completed 201 registration. Non-success HTTP or malformed content is a visible source/import error, not an empty calendar.

Plan/validate the complete diff and allocate UUIDv7 IDs for planned creates before mutation so the representative can name the full final set. Every changed row emits its ordinary window event for evaluator and outbound-calendar consumers. One deterministic representative (smallest changed window ID) also carries the complete sorted changed ID set in `calendar: {feed_id, revision, window_ids}`. Other events carry `{feed_id, revision}` only. Revision is a new UUIDv7 for each successful mutation batch, including horizon extension/feed deletion; retry redelivers stored events unchanged. This makes payload growth linear. #151 requests one calendar run only from the representative, using `calendar:{feed_id}:{revision}` and the complete set through existing `requestRun`. A run claimed before later individual events remains complete. No mutable feed lookup supplies the revision, and no direct run starts in the importer. This bounded consumer correction is part of the #139 integration, with #79/#151 alignment required.

## Validation and evidence

Window write instants use a positive four-digit year and at most millisecond precision, matching the existing Date-based window persistence/view boundary; finer precision is rejected locally rather than silently truncated. Shared Instant stays unchanged.

WIN-8 error pointers: past or beyond-90-day start at `/starts_at`; reverse/equal non-commute end and over-12-hour duration at `/ends_at`; invalid zone at `/tz`; recurrence shape/date failures at their nested fields. Keep all independently detected field errors. Exactly 12 hours and exactly 90 days are allowed; zero-duration commute is allowed, zero-duration class/event is not. Strict schemas reject spoofed provenance, guest flags and unknown nested recurrence fields.

Deterministic tests use only isolated fixtures/doubles. Database integration must exercise real tenant isolation, immutable migrations, ledger hash verification, event writes, replay idempotency and consumer run creation. Explicit acceptance fixture: anchor Monday 2026-11-16 09:00 MYT, Monday/Wednesday, through 2026-12-23 or `count:12`, skip 2026-11-25; both produce 11 occurrences. A source event end-time edit keeps the window ID, changes ends_at once, emits times_changed=true and creates a calendar run containing the full changed set.

Local tests are core evidence only. Real public-calendar refresh/run, production worker deployment and guest/share readiness remain separately unverified. No seeded production event may stand in for that check.
