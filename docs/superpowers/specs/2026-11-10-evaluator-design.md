## Approaches

1. A minute polling loop is simple but violates D45 and the Neon sleep budget. Rejected.
1. Event evaluation with memory-only timers or after-commit scheduling alone is small, but loses deadlines and source fanout after crashes. Rejected.
1. Event evaluation, transactionally persisted state and deadline intent, due-time Cloud Tasks, and recovery during the existing 15-minute batch. Selected: the minimum durable design that satisfies concurrency, crash recovery and D45. It costs a small amount of evaluator-owned coordination storage and task deletion IAM; it introduces no general workflow framework.

## Authoritative inputs

All SQL belongs in `packages/db/src/evaluator/`. Read binding rows in tenant context. `withSystem` can enumerate projects/organisations but cannot see arbitrary tenant `project_source` rows; never bypass RLS or assume a cross-tenant join works. Enumerate organisations, return from the system transaction, then perform tenant reads sequentially. This also respects `shareSystemConnection`'s prohibition on nested `with*` transactions.

History uses actual DB rows, not GCS capture heads or fixture imports. Filter readings by both `observed_at <= tEval` and `received_at <= tEval`, then select latest revision per `(source_id, metric, observed_at, coalesce(item_key, ''))`, ordering by revision, received time and ID for deterministic ties. Do not select one row per source, metric, or timestamp alone: MET has multiple items. Keep numeric `value`, `value_text`, `value_json`, item key, revision and genuine receipt time. A later revision must not erase the earlier revision from an evaluation before the later receipt.

Poll history for live freshness includes `purpose = 'poll'`, including `error` and `unchanged` with their actual status and original `started_at`. A backfill success cannot recover a failed live poll; a backfill failure cannot put a live feed into error. Readings from legitimate backfills remain recorded observations, subject to receipt cutoff. Neither source observation heads nor fresh batch time may replace observation/capture clocks. #120's heads fence late writes; they are not measurement history.

The initial correctness-first query reads all retained rows for the bound sources up to tEval, indexed by source/time, and returns all necessary pre-range history when callers request a range. Do not introduce arbitrary LIMITs that break three exact APIMS mornings, an old still-valid warning, a rain span's preceding four hours, or the prior observations/polls needed to recognize recovery. Optimize only from measured query evidence; any bounded replacement must prove the same history semantics. Expose `history(tx, {projectId, from, to})` for grades with `to` as the receipt cutoff and preserve prerequisite history before `from`.

A missing Crowd dependency must not roll back a successfully evaluated Sky pack: isolate each pack with a DB savepoint while retaining the failed pack as an explicit pending reevaluation/error. Never mark that pack Normal, successful or caught up.

Registry definitions come exclusively from the real `SourceAdapter.indicators` declarations in `@skyclause/sources` (and a real forecast-owned definition provider when #127 establishes one). Build a deterministic name-sorted registry, collapse identical definitions, reject conflicting definitions. Include registered definitions even for unbound kinds so the engine can represent missing inputs with `sourceId: null`. Do not infer CEL types from names, defaults, SOURCE_METRICS, readings or TEST_REGISTRY. Empty/missing providers are explicitly unavailable. `packages/sources/src/adapters/index.ts` is currently empty: integration readiness cannot be claimed now.

Project camera hours may enrich the project snapshot's source metadata from real settings. Rapid Rail pending metadata comes from the newest eligible `metadata` reading; use its `next_update_utc` (contract-confirmed UTC) for the engine's `meta.next_update`, keeping the raw source field intact. GTFS `calendar_end` comes from the newest eligible `feed` reading and is inclusive through that local date; stale begins at the following MYT midnight even if polls succeed. Validate through SOURCE_METRICS schemas; malformed metadata is a dependency/data error, never a guessed date.

Two narrow engine integration changes are necessary: preserve the full observation/item identity in `dedupeReadingsAt` before any intentionally item-specific indicator selection, and implement GTFS calendar expiry in `resolveSourceAt` using the supplied real feed metadata. Preserve existing error precedence, recovered-first-reading, camera probation and off-hours rules. Export the existing source-resolution and effective-span helpers as a small supported seam so evaluator code does not duplicate hidden freshness/span rules. No broad engine refactor.

## Snapshots and published sheets

Implement the existing contract signatures unchanged. `SnapshotSource.take(tx, {projectId, pack, tEval, windows, persist})` loads history and registry, invokes real `snapshotAt`, and returns a full frozen snapshot. Sky never calls ForecastSource. Crowd calls real `ForecastSource.nights` over the relevant local-date range (current date plus supplied window dates), preserves null exits/no-call reasons, adds nights before computing the final canonical snapshot hash. Until #127 supplies a provider, Crowd returns explicit `b-forecast` unavailability; no runtime empty-night double. Tests may inject it.

`persist: false` performs zero writes, including no registry-history writes, source-state updates, deadline writes or audit events. `persist: true` inserts once per `(project_id, pack, t_eval)`, with a database unique constraint and reload on conflict. Existing rows are immutable; return their verified body, not newly calculated data under an old ID. Missing archival body on a legacy row is explicit unavailability, not reconstructed success. The worker serializes evaluation time and refuses backward state updates; previews at historical times never mutate live state.

Persist the complete engine snapshot, not only its current four decomposed JSON columns. The runtime emits `warningObservations` and `registryHash`; #135 validates both but `indicator_snapshot` currently drops them. Add nullable legacy-compatible `snapshot_body`, `registry_definitions` and `windows` JSON columns, populate them on all new evaluator writes, and keep existing inputs/site/series/nights/hash columns consistent. Unknown legacy provenance stays unknown. Historical registry lookup uses the exact stored definitions and checks their canonical hash. No generated types or timestamps are backfilled into old rows.

`ShadowEvaluator.loadPublished` follows `project_pack.sheet_id -> clause_sheet.live_version_id -> sheet_version`, requires the selected version to belong to that sheet and pack and to be published with a positive n, parses content, verifies contentHash and invokes real `check(content, registry)`. Do not fabricate CheckedSheet by attaching hashes: the engine also needs authoritative `registryTypes`. Do not UPDATE System v1 to add validation data; publication is immutable. `evaluate` delegates to engine `evaluate` and `explain`; `verdictHash` remains the actual engine `Verdicts.hash`.

#135's `RuntimeIndicatorRegistry.load(tx, {projectId, pack, registryHash?})` and snapshots are composed from these providers. Its `recordedAt` port remains null until there is authoritative historical window/binding metadata; current mutable windows cannot masquerade as historical context. Stored-run publish previews can work through verified full snapshots and stored registry definitions without claiming arbitrary-time replay. This limitation remains explicit under #136.

## Transactions and transitions

Acquire a project coordination advisory lock before any pack locks; pack locks are keyed by project and pack. The project lock serializes its single next-deadline replacement; the pack lock defines the promised evaluation seam for other callers. Acquire multiple source locks in sorted ID order and never acquire a project lock while holding a source lock. Query project/archive, pack enablement and the organisation `pack_crowd` flag again under the lock. Skip archived/suspended projects, off packs, disabled Crowd, cancelled windows and windows beyond their latest enabled clause span. Do not delete historical snapshots/crossings to implement skipping.

Select non-cancelled windows from creation through the latest relevant clause span, including future windows (which may yield `not_open`), zero-length commute waves and the exact terminal instant. Existing implicit rain span is end−30m to end+60m. The boundary helper must share this logic with `evaluate`; an expired window's old row is not a new Normal crossing. Site evaluation always happens even when there are zero windows.

Compare scope verdicts with `canonicalHash({mode, watch, noCall: null | sortedUniqueInputNames, recommendations: sortedUniqueRecommendations})`. Do not use engine verdict hash, values, ages, source IDs, since times, clause detail or recommendation order as the crossing comparison. Missing scope state compares with Normal/false/null/empty. First Normal creates shadow state without a crossing; first No call or Watch is a crossing. Update full shadow details on evaluation, preserving `since` until the semantic key changes. Crossing, full snapshot, shadow update and `emitEvent('crossing.detected')` are one tenant transaction; any event error rolls everything back. Database lock plus snapshot uniqueness and event/message receipts make repeated/concurrent evaluation idempotent. Older tEval cannot overwrite newer shadow state.

Source freshness is a global row with tenant-scoped events. Add an evaluator-owned immutable source-transition record with transition ID, source ID, evaluated time, old/new state, since/status/pending and frozen recipient `(orgId, projectId)` pairs. Gather current active bindings through tenant reads, then under the source advisory lock compare/update `source_state` and append the transition atomically. Keep a completed marker on the durable delivery intent, not an append-only domain row. Source ingestion's `sources:<id>` lock is the shared fence while reading its committed history. A source transition must not be inferred separately per pack.

Drain each transition in order. For each frozen recipient, use its tenant transaction and `handleOnce(..., {messageId: transitionId + ':' + projectId})` to emit exactly one source event. Recheck binding/archive eligibility; a removed binding or archived target is acknowledged as skipped. Only after all recipients are handled mark delivery complete. A crash after the first recipient or after emission but before completion retries without duplicates. A subsequent recovery must not overwrite an undelivered stale/error transition. Evaluate affected eligible project packs after fanout through their own idempotent boundary. Use `source.error` for entry into error, `source.stale` for entry into stale, and `source.recovered` on return from error/stale to recovered/fresh; recovered→fresh does not send a second recovery. Other states are stored without inventing new domain event types.

## Deadlines and delivery

Add one tenant evaluator-deadline row per project: generation UUID, next due instant or null, evaluated time, desired task name, last scheduled task name and delivery status. It is a durable intent, written in the evaluation transaction. A task body carries `{org_id, project_id, generation, due_at}`; no trust is placed in arbitrary source IDs in task bodies. Replacement increments generation, creates the new generation-specific task, then deletes the old task, acknowledging 404/409 idempotently. A task already dispatched can survive deletion; generation comparison under the project lock makes it harmless. Retry a failed create/delete from the next existing 15-minute batch; do not rely only on `afterCommit`, whose errors are logged and swallowed by the DB library.

Use a dedicated `evaluator-deadlines` queue. The existing `cloudTasks` helper only creates, existing queues omit this queue, and enqueuer IAM does not grant delete. Add a narrowly scoped evaluator task transport with create/delete, queue-scoped worker task deletion permission, and reuse the established worker invoker OIDC audience/email checks and existing serviceAccountUser grant. Do not broaden unrelated queues or apply Terraform in implementation tests. Queue creation/IAM/deployment proof is a separate real-environment check.

Compute the earliest strictly-future time at which existing data could change evaluation: source freshness boundaries, pending expiry, GTFS calendar expiry, camera daylight boundaries, MET validity bounds/forecast date rollover, APIMS required morning rollover, applicable rain rolling-grid changes, and clause span opening/terminal completion. Respect engine inequalities: age uses floor(seconds) and staleness is `ageS > staleAfterS`, therefore a 600-second threshold becomes stale at basis+601 seconds; terminal span behavior differs at equality versus after. No polling every minute, no blind fixed-frequency Cloud Task loop, and no immediately re-enqueued past deadline. Test the planner by comparing engine results immediately before/at/after its chosen boundaries. A known unsupported temporal dependency is an explicit implementation failure, not a missed timer.

`readings-updated` validates `ReadingsUpdated` and persisted poll/source identity for positive insertions. Source120 deliberately publishes that message only when new_rows is positive, so also consume the existing tenant `poll.recorded` domain event for error and unchanged polls. Validate its persisted source/poll/project association and deduplicate the same project/poll across both routes. Never depend on a zero-row Pub/Sub message that the producer does not send. Evaluate only actual bound targets. Domain events use `onEvent`/`handleOnce` for window.created/updated/cancelled, clause_sheet.published and source.bound/unbound. For durable retries, those handlers commit a project reevaluation intent in the supplied transaction; drain after commit and in the batch, rather than opening nested tenant transactions. The 15-minute batch drains pending reevaluations, transitions and task intents and bootstraps active projects lacking shadow/deadline state. No evaluator entry is added to `ticks`. Device pushes may trigger immediate evaluation; scheduled source polling still writes only through #120's batch.

## Acceptance conflicts and rulings

- **D45 versus exactly one CLS-4 crossing:** 15-minute storage and a 10-minute gauge stale limit can generate genuine No call between batches. Example: a 15:00 batch with latest 14:55 observation becomes stale at 15:05:01, before the 15:15 batch. A 15:30 commute wave has an open span then. Root ruling during this planning turn: preserve every genuine No call/recovery transition, retain the required mode change at the actual 15:15 batch, and align #133/#79 before implementation claims. The replay must produce a concrete trace from actual engine behavior, not a guessed total or prior mode. Do not widen freshness, change cadence/batching or suppress deadlines. Cost: extra No call/recovery transitions and a possible beta usability gap under 15-minute buffering/10-minute freshness, tracked as explicit production acceptance.
- **Capture versus simulated receipt:** the existing JPS bytes were captured 5 November and contain 2 November values. Tests may label a reconstructed Nov-2 poll/batch schedule explicitly, but cannot claim those receipt clocks were captured live. A live DB history query never substitutes simulated clocks. Use distinct fixture provenance and simulation labels.
- **CLS-11:** the real APIMS capture proves CA16W=67 at 21:00 MYT, captured 21:13. With default severe-haze requirements, missing three mornings can yield No call even while `haze_watch` is `not_fired`. Assert the named clause/indicator, and do not invent absent morning history to force an overall Normal verdict.
- **Timing precision:** preserve the current engine's strict stale inequality, not an assumed 10:00.000 transition. A contract change to exactly 10 minutes belongs in a separately reviewed engine adjustment, not silently in the worker.
- **Historical context:** current mutable bindings/windows and today's metadata do not prove past project configuration. `recordedAt` stays unavailable; exact stored-run replay uses its frozen inputs and registry. Cost: arbitrary-time sheet replay remains gated on #136.
- **Production readiness:** missing providers and inactive auditor are explicit partial acceptance. Merge of tested core code must not auto-close #133 as fully live-complete; list remaining acceptance under #557 or the existing owning issues before any closure decision.
